# Why CUDA 12.8 / torch 2.9.1: the cluster's "rtx6000" gres is the RTX PRO 6000
# Blackwell (compute capability 12.0). torch 2.4.1+cu124 and the prebuilt gsplat
# pt24cu124 wheel (sm_70..sm_90 cubins only) cannot run there, so this env is
# built on cu128 wheels + a source-built multi-arch gsplat (8.0;8.6;9.0;12.0).
#
# Fully pinned (generated with `uv pip compile` on 2026-09-04, glibc 2.41 /
# manylinux_2_31 needed by the open3d wheel). Top-level choices:
#   numpy 1.26.4      == main pipeline .venv pin; openpi-client needs numpy<2 and
#                        several agents/* stages still call ndarray.ptp (gone in 2.x)
#   open3d 0.19.0, trimesh 4.12.2, plyfile 1.1.3, scipy 1.17.1, pydantic 2.13.4,
#   websockets 16.1.1, msgpack 1.2.1, pyyaml 6.0.3, imageio 2.37.0, pytest 9.0.2
#                     == main .venv pins (agents.core.common is written against them)
#   mujoco 3.12.0, viser 1.1.0   -- current releases, verified (see README.md)
#   utils3d           -- PyPI's "utils3d" is an unrelated package (pins open3d<0.14);
#                        the one agents.core.common / interface/*viewer.py use is
#                        EasternJournalist/utils3d (wxyz quaternions), pinned to tag 1.7
#   gsplat 1.5.3      -- NOT here: its sdist imports torch at build time, so
#                        setup_env.sh installs it afterwards with
#                        BUILD_NO_CUDA=1 uv pip install --no-build-isolation gsplat==1.5.3
#                        and the CUDA backend is JIT-built at first import.
#   openpi-client     -- local path /group/worldcept/code/openpi/packages/openpi-client,
#                        installed by setup_env.sh; its deps (dm-tree, tree, msgpack,
#                        numpy<2, pillow, websockets) are pinned below.
